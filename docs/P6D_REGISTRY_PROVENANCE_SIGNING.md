# P6-D — Registry, Supply-Chain Provenance and Signing

This phase defines a manual, controlled release path for the four BankCore-owned images:

- `ghcr.io/joaop-gregorioDS/bankcore-auth`
- `ghcr.io/joaop-gregorioDS/bankcore-transactions`
- `ghcr.io/joaop-gregorioDS/bankcore-risk`
- `ghcr.io/joaop-gregorioDS/bankcore-audit`

The workflow is `.github/workflows/p6d-release.yml`. It is deliberately triggered only by `workflow_dispatch`; it does not deploy, access the VPS, or publish on every push to `main`.

## Release identity

Human-readable tags are navigation aids. The generated `manifest.json` is the release contract and uses the registry digest as the image identity:

```text
git commit
  -> GHCR image
  -> sha256 digest
  -> CycloneDX SBOM
  -> GitHub artifact attestations
  -> Cosign keyless signature
```

The verifier checks that the manifest digest, the pulled GHCR image, the signature subject and the attestation subject all identify the same image. The production-like E2E consumes only the manifest's `image@sha256:...` references.

## Permissions and trust model

The publish job uses only the permissions required for this controlled release:

- `contents: read`
- `packages: write`
- `id-token: write` for OIDC-backed keyless signing and attestations
- `attestations: write` for GitHub artifact attestations

No private signing key is stored in repository or environment secrets. No application secret is passed as a Docker build argument. Runtime-only secrets are generated by the disposable E2E runner.

The exact keyless certificate identity is bound to this repository, workflow file and ref. A verification failure is a release failure; it is not suppressed.

## SBOM and third-party images

Each BankCore-owned image receives a CycloneDX JSON SBOM and corresponding registry attestations. Third-party infrastructure images are not republished by this workflow. Their current tag/digest status is recorded in [THIRD_PARTY_IMAGE_INVENTORY.md](THIRD_PARTY_IMAGE_INVENTORY.md); P6-D does not claim that every upstream tag has been converted to a digest pin.

## Verification

The real proof requires a manual GitHub Actions run with GHCR package access. The `verify` job performs:

1. manifest generation from CI-produced fragments;
2. digest pull and Docker identity check;
3. Cosign keyless signature verification;
4. GitHub artifact provenance verification;
5. SBOM format and sensitive-marker checks;
6. migrations and PIX-to-Audit E2E using digest-pinned images;
7. teardown and residue checks.

P6-D is not complete until this manual workflow run is green. Local P6-C remains the local fallback for builds that have not been published to GHCR.
